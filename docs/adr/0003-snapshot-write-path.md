# ADR-0003: 랭킹 스냅샷은 Spring만 DB에 쓴다

- 상태: 확정
- 날짜: 2026-10-14
- 담당: 김송은

## 배경

조회 API는 "최신 스냅샷 = `ranking_type`별 `MAX(snapshot_at)`"으로 읽는다. 집계 row(TOP100)가 나뉘어 INSERT되면, 조회가 일부만 들어간 스냅샷을 최신으로 보게 된다.

## 결정

1. **AI 서버(FastAPI)는 DB에 직접 쓰지 않는다.** 집계 결과를 Spring 내부 API로 전달한다.
2. **Spring은 집계 하나(한 `ranking_type` + 한 `snapshot_at`)를 한 트랜잭션으로 INSERT한다.** 커밋 전에는 조회에 보이지 않으므로 최신 스냅샷은 항상 완결된 결과다.
3. 따라서 스냅샷 완료 여부를 표시하는 테이블이나 컬럼은 두지 않는다.

## 검토한 대안

- 완료 표시(별도 테이블이나 `is_complete` 컬럼): 스키마와 조회 조건이 복잡해진다. 쓰는 쪽이 하나뿐이라면 트랜잭션만으로 충분하다.
- AI 서버가 DB에 직접 INSERT: 트랜잭션 경계를 Spring이 보장할 수 없고, 스키마 변경이 두 서버에 퍼진다.

## 결과

- 내부 수집 API의 스펙과 인증(내부용 API Key 헤더)은 별도 이슈로 다룬다.
- 다른 경로로 RANKING_SNAPSHOT에 쓰게 되면 이 ADR을 다시 검토한다.
